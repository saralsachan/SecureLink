The problem

Browser agents see everything. Including the things you didn't ask them to.

Today's automation doesn't ask permission — it screenshots your inbox, reads your session, hands your typed password to a model in some data center. That's why most people won't let an agent near their accounts.

A naïve agent

Full screenshot of the page — password field included — is sent to the model verbatim.

  • Redoable on every keystroke
  • You find out later, if ever

How it works

Look. Redact. Then act.

Every step before the network is on-device. The server — when used — only ever receives the sanitized result.

  1. 01

    Perceive the page

    A structural map of the tab (DOM boxes + roles + labels) is built in-browser, and a small local ViT runs straight on the screen — faces, text, UI — all inside a Web Worker.

  2. 02

    Redact sensitive content

    A dual-channel detector (DOM rules + vision/OCR) flags passwords, emails, card numbers and faces. Values become [REDACTED_EMAIL_1]-style tokens; the mapping back to the real DOM is kept in your browser only.

  3. 03

    Decide, confirm, act

    A tiered reasoner chooses the next action — local heuristics first, VLM reasoning only if needed. Clicks, typing and navigation pause on a confirmation dialog you approve, and the action executes against the real element via the local token map.

In automatic mode the server layer adds a privacy firewall, VLM planning and grounding — and the firewall re-checks everything the model could still see. In local-only mode the network is never touched at all. Full architecture →

Security by construction

Privacy is not a toggle. It's the pipeline.

Redact, then send

Sensitive regions are detected and neutralized on the page before anything leaves the tab. The network never sees raw credentials.

Dual-channel detection

DOM rules catch structured fields while a local vision model + OCR catch everything else — faces, on-screen text, unusual layouts.

Token map stays local

[REDACTED_EMAIL_1] is all that travels. Rules resolving tokens back to real elements live in the browser and are used only when executing actions.

Second pair of eyes

The server-side privacy firewall re-scans what the model receives — leaked PII, faces, Luhn-valid cards get blocked before they reach the model.

Ask before you act

Every sensitive action — typing, clicking, navigating — pauses on a clean confirmation dialog in the page. Automation is gated, never silent.

A real audit trail

Every redaction and action is logged with timestamps and token-level summaries — never raw values. Reviewable in the popup, kept only in the session.

Performance & resilience

Fast on-device, layered reasoning — and it never hangs.

Built to feel instant on a laptop-class machine, with clear degradation instead of freezes when any stage is unavailable.

  • INT8-quantized vision. The MobileViT + YOLO-family models run locally inside a Web Worker, so perception never blocks the page's UI thread.
  • Delta state sync. Only changed DOM regions are re-extracted and re-redacted on later steps; the structural map is cached per site and session.
  • Tiered reasoning. Local heuristics decide trivial steps (scroll, obvious clicks) with zero network; the local ViT confirms; the server VLM is used only when human-level understanding is genuinely needed.
  • Graceful degradation. Every stage is wrapped: a dead model, an unreachable server, or a timeout surfaces as a readable error — the tab never hangs, and no partial or unredacted payload is ever sent.

FAQ

Questions, answered.

Does the server ever see my password?

No. Values become anonymous tokens — [REDACTED_EMAIL_1] — on-device before anything leaves the tab. The server receives only the sanitized structural map and redacted screenshot, and the privacy firewall re-checks both layers before they reach a model.

Is a server required at all?

No. Local-only mode runs entirely in the browser with deterministic heuristics — no setup, no keys, no network. Automatic mode adds VLM planning and multi-step reasoning via the Agent server (localhost:8000 by default).

Which browsers and pages does it support?

Edge and Chrome (Manifest V3). The content script runs on any page. Cross-origin iframes and shadow DOM are flagged rather than inspected directly — their contents are only reachable through the screenshot path.

How do I know it actually redacted something?

The popup shows a redacted screenshot preview side by side with the raw frame, and every redaction is recorded in a token-level audit log you can review in the session — timestamps included, raw values never.

How much does it cost?

The extension is free and the perception models run on-device. Automatic mode only costs if you pay for a VLM API key — or point the server at a free local Ollama install.

Get started

Running it takes about five minutes

1

Build the extension

cd extension
npm install
npm run build   # → dist/
2

Load it unpacked

Open edge://extensions (or chrome://extensions), enable Developer mode, and Load unpacked the extension/dist folder. Pin the icon.

3

Run the demo page

# keep port 8000 free for the agent server
python -m http.server 3000 --directory extension

Open http://127.0.0.1:3000/test.html, click the SecureLink icon, and press Run. Toggle Local-only mode to go fully offline.

4

(Optional) Start the agent server

cd inference-server
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
cp .env.example .env        # add a VLM key
.venv\Scripts\python -m uvicorn server:app --host 0.0.0.0 --port 8000
